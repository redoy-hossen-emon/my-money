# My Money

My Money is a personal finance dashboard built with Next.js and MongoDB. It lets users create an account, record income and expenses, review cash flow, and manage account settings.

## Features

- Registration and login with password hashing and signed HTTP-only sessions
- Dashboard with balances, recent transactions, spending categories, savings targets, and cash-flow charts
- Add-money and spent-money transaction forms
- Reports page with transaction history
- Profile settings for name, email, and password changes
- Preferences for currency, opening page, and reduced motion
- Profile-menu logout flow
- Responsive layout for desktop and mobile screens

## Tech Stack

- Next.js 16 App Router
- React 19
- MongoDB Atlas with the official MongoDB Node.js driver
- `bcryptjs` for password hashing
- CSS Modules for component styling
- ESLint with the Next.js configuration

## Build The Project Step By Step

### 1. Create the Next.js project

Create a Next.js application with the App Router and JavaScript support. Install the project dependencies:

```bash
npm install next react react-dom mongodb bcryptjs
npm install --save-dev eslint eslint-config-next
```

The available scripts are:

```bash
npm run dev      # start the development server
npm run lint     # run ESLint
npm run build    # create a production build
npm start        # serve the production build
```

### 2. Create a MongoDB Atlas database

1. Create a MongoDB Atlas project and cluster.
2. Create a database user with read and write access.
3. Add your development IP address under **Network Access**. For temporary local testing, Atlas also supports `0.0.0.0/0`, but a restricted IP range is safer.
4. Copy the connection string from Atlas.
5. Create a `.env` file in the project root. `.env` is ignored by Git and must never be committed.

Example format:

```env
MONGODB_URI=mongodb://username:password@host-1:27017,host-2:27017,host-3:27017/my-money?authSource=admin&replicaSet=your-replica-set&retryWrites=true&w=majority&tls=true
AUTH_SECRET=replace-with-a-long-random-secret
```

Atlas normally provides a `mongodb+srv://` URI. This project uses the explicit replica-set form because some Windows DNS environments refused Atlas SRV lookups. Use the host names, replica-set name, and credentials generated by your own Atlas cluster.

### 3. Build the shared server utilities

- `src/lib/mongodb.js` creates and caches the MongoDB client.
- `src/lib/auth.js` signs and verifies session cookies.
- Passwords are stored only as `bcryptjs` hashes.
- The database name used by the API is `my-money`.

### 4. Add the application routes

The top-level `app` directory contains the pages and API routes:

```text
app/
	page.js                         dashboard
	login/                          login page
	register/                       registration page
	add-money/                      income form
	spent-money/                    expense form
	reports/                        transaction reports
	profile/                        profile and password settings
	preferences/                    local display preferences
	api/auth/login/                 login endpoint
	api/auth/register/              registration endpoint
	api/auth/logout/                logout endpoint
	api/auth/profile/               profile read/update endpoint
	api/dashboard/                  dashboard data endpoint
	api/expenses/                   expense endpoint
	api/reports/                    reports endpoint
	api/transactions/               transaction endpoint
```

### 5. Add the reusable UI

Shared client components live in `src/components`:

- `Header` loads the current user, displays the balance, and owns the profile submenu.
- `Dashboard` renders the chart and financial overview.
- `AuthForm` handles login and registration.
- `AddMoneyForm` and `SpentMoneyForm` create transactions.
- `Reports` displays transaction history.
- `ProfileSettings` updates personal details and passwords.
- `Footer` completes the shared page shell.

### 6. Protect private pages

Server-rendered private pages call `getPageSession()` and redirect unauthenticated users to `/login`. API routes call `getRequestSession(request)` and return HTTP 401 when the session is missing.

### 7. Run and verify the project

Start the app:

```bash
npm run dev
```

Open `http://localhost:3000/register`, create an account, add an income and an expense, and verify the dashboard and reports. Then test the profile menu, password change, preferences, and logout.

Before sharing or deploying the project, run:

```bash
npm run lint
npm run build
```

## Database Collections

The application creates these collections as data is added:

- `users`: user ID, name, email, and password hash
- `income`: income transactions linked by `userId`
- `expenses`: expense transactions linked by `userId`

Every private transaction query filters by the signed-in user's `userId`, so users see only their own financial data.

## Challenges And Solutions

### MongoDB Atlas DNS failures on Windows

The first connection attempts failed with:

```text
querySrv ECONNREFUSED _mongodb._tcp.cluster0...
```

Windows could resolve the Atlas record in PowerShell, but the Node.js MongoDB driver could not reliably resolve the `mongodb+srv` record inside the Next.js process. The project initially tried configurable public DNS servers and explicit SRV resolution. The stable solution was to use Atlas's three replica-set hosts in a standard `mongodb://` URI, avoiding SRV discovery during application startup.

### Cached development connections

Next.js development mode can preserve a connection promise on `global`. After changing `.env` or connection code, the server must be fully stopped and restarted. Clearing `.next` can also be useful when an old Turbopack parse result appears.

### Keeping credentials out of logs and source control

Connection errors are converted into safe API responses without exposing the URI. Environment files are ignored by Git. Any credentials that have been exposed during local debugging should be rotated in MongoDB Atlas and replaced in `.env`.

### Readable chart labels

The one-month chart contains daily points, which caused every date label to overlap. The chart keeps all data points for accurate lines but displays only spaced day numbers. Longer ranges use compact month labels.

### Authentication boundaries

Authentication had to work consistently across server pages, API routes, the header, and logout. The solution uses one signed HTTP-only cookie, server-side route guards, API session checks, and a client-side logout request that refreshes the router after clearing the cookie.

## Project Cleanup

The default Next.js starter pages and SVG assets were removed once the finance dashboard replaced them. Generated `.next` output and installed `node_modules` remain local-only because they are excluded by `.gitignore`.

## Security Notes

- Use a strong random `AUTH_SECRET` in production.
- Restrict MongoDB Atlas network access to trusted IP ranges.
- Rotate any database password that has been exposed during development.
- Never commit `.env` or paste real credentials into documentation.
